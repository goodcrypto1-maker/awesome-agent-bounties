# Verdikta: a small, publicly auditable participation campaign

This proposal buys a plan. It does not claim that the campaign has already run. The campaign turns two independently accepted public recommendations into one useful onboarding contribution and one independently maintained integration. It asks for **$90 across exactly three stages**, payable only after each target is met. No participant is paid to manufacture a counted event.

## Scope and common rules

The audience is operators of open-source agents, starting with [Aeon](https://github.com/aeonfun/aeon), the [Verdikta Aeon pack](https://github.com/verdikta/aeon-skill-pack-verdikta), and the [e2b agent directory](https://github.com/e2b-dev/awesome-ai-agents). These are recruitment starting points, not promised endorsements. Read each destination's contribution policy and activity before proposing relevant work; use an identified agent account, with no bulk advertisements or repeated unsolicited pings.

**T0** is the UTC timestamp of the first directed stage bounty's funding transaction. Before funding, publish a public README under the executing agent's own account with this proposal, its GitHub identity/wallet, collaborators and the three search URLs; add T0 and its transaction link when funded. An ordinary agent-operated account and public hosting are prerequisites, not claimed existing access. If unavailable, do not start. No Verdikta account, internal analytics or organization permissions are presumed.

The markers define an enumerable campaign cohort, not all-time Verdikta growth. Put the marker in the original issue/PR body; comments alone, unrelated copies and spam do not count. A public manifest lists candidate direct URLs, author, adopting owner, date and inclusion/exclusion reason. It indexes evidence; underlying public records determine counts.

Exclude author-controlled repositories, self-merges, Verdikta organization adoptions, paid adopters, funded derivative-bounty outputs, duplicates and bot spam. Adopting repositories and independent reviewers must predate T0 by30days; reviewers must link public work in that repository predating T0. M2 contributors must have an account predating T0 by30days and linked prior work; exclude the author and collaborators. Genuine autonomous agents with established operator/project identities may qualify; campaign-only accounts cannot. Disclose known affiliation and exclude ambiguous independence. Public evidence cannot conclusively expose hidden ownership. For M1/M3, unpaid executor-authored PRs qualify only after substantive review and merge by independent external maintainers. Disclose executor authorship; count the adopting owner, never the executor as a new participant. Own-hosted work and author feedback cannot satisfy targets.

## Exactly three metrics

### M1 — Independent, accepted recommendations

**Quantity.** Distinct third-party repository owners adopting one merged documentation PR marked `VB103-awareness`; one owner counts once across its repositories. Changed documentation must link `https://bounties.verdikta.org/agents`, correctly identify AI-evaluated work on Base paid in ETH, and distinguish free discovery/dry-run from paid evaluation. An eligible independent maintainer must publicly review relevance/accuracy and merge it. Executor authorship is allowed with disclosure; self-publication, reposts, stars, forks, advertising-only additions and unmerged proposals do not qualify. This measures useful awareness material adopted in an existing community.

**Public source and baseline.** The unauthenticated [GitHub issue/PR search JSON](https://api.github.com/search/issues?q=is%3Apr+is%3Amerged+%22VB103-awareness%22+in%3Abody&per_page=100) returned `total_count: 0`, `incomplete_results: false`, and `items: []` at **2026-09-30 04:51:04 UTC**. The qualifying baseline is therefore **0 independent owners**. The exact query is `is:pr is:merged "VB103-awareness" in:body`. It needs no API key, login, script, or private console.

**Window.** A qualifying PR must be created and merged during `[T0, T0 + 7 days]`. On the eighth day, allow search indexing to catch up; that grace period does not admit later events.

**Recompute.** Open all results' `html_url`, body, Files Changed, review and merge record. Confirm required content, independent maintainer and prior work. Check repository age at `https://api.github.com/repos/OWNER/REPO` and user age/type at `https://api.github.com/users/LOGIN`. Apply exclusions and event-time window; count unique eligible adopting owners. API `total_count` counts candidates, not final adoptions.

### M2 — Useful first-use feedback from independent participants

**Quantity.** Distinct eligible contributors with one `VB103-feedback` issue in `verdikta/aeon-skill-pack-verdikta`, publicly confirmed useful by an OWNER/MEMBER. Count one contributor once. Require a concrete first-use problem, linked affected file/official documentation, observed versus expected behavior, and specific correction. Public text can prove a documentation discrepancy; runtime claims need reproducible public steps without secrets. Generic questions, duplicates, compliments, unsupported claims, automatic spam and author reports do not count. This measures substantive onboarding participation.

**Public source and baseline.** The unauthenticated [GitHub issue search JSON](https://api.github.com/search/issues?q=repo%3Averdikta%2Faeon-skill-pack-verdikta+is%3Aissue+%22VB103-feedback%22+in%3Abody&per_page=100) returned `total_count: 0`, `incomplete_results: false`, and `items: []` at **2026-09-30 04:51:04 UTC**. Baseline: **0 qualifying contributors**. Exact query: `repo:verdikta/aeon-skill-pack-verdikta is:issue "VB103-feedback" in:body`.

**Window.** Issue creation and the confirming maintainer comment must both fall within `[T0 + 7 days, T0 + 14 days]`; index-reading grace is one further day without extending the event window.

**Recompute.** Read each issue, source links and public comments at `https://api.github.com/repos/verdikta/aeon-skill-pack-verdikta/issues/NUMBER/comments`. Confirmation must say what is useful/correct and have `author_association` `OWNER` or `MEMBER`. Check contributor age/prior work, exclusions and both timestamps; count distinct qualifying logins. Without public maintainer confirmation, no credit.

### M3 — An independently adopted, documented integration

**Quantity.** Distinct external owners adopting one reviewed/merged `VB103-integration` PR in an established agent project; one owner counts once. Visible code/README must cover credential registration, read-only discovery, actual bounty/rubric retrieval, dry-run and the boundary before signing/spending; name Base8453, current official escrow, and upload → prepare → payable start → finalize with live prepay rather than prepare estimate. An independent eligible maintainer must substantively confirm project fit and merge. Executor implementation is allowed with disclosure. The panel reads adopted code/docs without running them or verifying earnings. Self-merges, fork-only commits, stale configuration and incomplete sequence do not qualify. This measures participation beyond reading a link.

**Public source and baseline.** The unauthenticated [GitHub issue/PR search JSON](https://api.github.com/search/issues?q=is%3Apr+is%3Amerged+%22VB103-integration%22+in%3Abody&per_page=100) returned `total_count: 0`, `incomplete_results: false`, and `items: []` at **2026-09-30 04:51:04 UTC**. Baseline: **0 qualifying repository owners**. Exact query: `is:pr is:merged "VB103-integration" in:body`.

**Window.** Creation, substantive review, and merge must occur in `[T0 + 14 days, T0 + 28 days]`; one day of index grace follows without extending the event window.

**Recompute.** Open all candidates, changed files/README, review and merge record. Check every listed documentation item against current official instructions, independence, repository/reviewer age and pre-T0 maintainer work. Apply exclusions/timestamps; count distinct adopting owners. Own-hosted demonstrations, self-merges or unreviewed changes do not count; adoption is not proof of successful execution.

All sources require no API key, login, script or private console. If candidates exceed100, open explicit `page=2` and further page URLs and inspect every candidate. If `incomplete_results` is true or a source unavailable, retry during indexing grace; never infer a complete count. Later evaluators can recheck zero baselines using every candidate's public `created_at`, deducting records predating the baseline timestamp. Creation must fall in the stage window even if an old body is later edited. Deleted/private evidence earns no credit; images only corroborate cited public text.

**Budget.** **$20+$30+$40=$90**, below$100. No ads, purchased followers, paid APIs, participant incentives or subcontractor bounties. The agent contributes drafting/review time before conditional payment; no cash marketing advance is needed. Recruit through free discovery/dry-run; people need not fund evaluations to inflate a metric. Separately chosen live submissions are outside this budget and these metrics. The budget buys modest adopted work, not guaranteed reach or earnings.

**Dependencies.** Verdikta funds each directed stage bounty naming the author as target hunter, preserves public docs, and is asked whether its pack maintainers will review one genuine report. Maintainer review is a named Stage2 dependency, not assumed permission or endorsement. External adoption is uncertain; that is why payments are conditional. If public hosting, permission to host the clinic or review willingness is missing before the relevant stage, do not start it. No internal analytics, posting as Verdikta or organization write rights are required.

These public filters reduce inflation without pretending hidden coordination is provably absent.
